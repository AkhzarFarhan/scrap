1. Compilation Pipeline, Linkage & ODR Toolchain
  • Pipeline: Preprocessor (#include macro expansion) $\to$ Translation Unit (TU) $\to$ Compiler AST & Type Check $\to$ LLVM IR/Optimizer $\to$ Assembler (ELF .o) $\to$ Linker (resolves symbols $\to$ binary).
  • ODR (One Definition Rule): Exactly 1 definition per TU. Inline functions/templates can appear in multiple TUs if token-identical; linker merges them (COMDAT elimination).
  • Linkage: Internal (static, anonymous namespace: visible in TU only); External (default non-static: exported to global symbol table); Module (C++20 export module).
  • Name Mangling: Encodes namespace, class, parameter types in symbols. extern "C" suppresses mangling for C ABI/kernel interop.
2. Memory Layout, Alignment & Strict Aliasing Hardware Alignment

Virtual Address Space: Text (Code, RO) $\to$ RODATA (constants) $\to$ Data (init globals) $\to$ BSS (zeroed globals) $\to$ Heap ($\uparrow$) $\to$ MMAP $\to$ Stack ($\downarrow$, fast 8MB).

  • Natural Alignment: A $k$-byte type must reside at address $A \equiv 0 \pmod k$. Compiler inserts structure padding. Re-order struct members from largest to smallest to minimize footprint.
  • Cache-Line Alignment: alignas(64) struct alignas(hardware_destructive_interference_size) SPSC; prevents false sharing across CPU cores.
  • Strict Aliasing Rule: Compilers assume pointers of different types never point to the same memory. Dereferencing reinterpret_cast<uint32_t*>(&float_val) is Undefined Behavior (UB).
  • Safe Modern Punning: Use C++20 std::bit_cast<To>(from) (constexpr, zero-cost) or std::memcpy. Compiler generates pure register-to-register moves.

4. UB vs Implementation-Defined vs Unspecified ISO Taxonomy
  • Undefined Behavior (UB): No requirements imposed. Compiler may assume UB never happens and optimize away critical checks (e.g. signed overflow, use-after-free, null dereference, data race).
  • Implementation-Defined: Behavior must be documented by compiler (e.g. sizeof(int), sign extension on right shift, endianness, structure padding layout).
  • Unspecified: Valid choice among alternatives, documentation not required (e.g. order of evaluation of function arguments prior to C++17, allocation address from malloc).

6. Object Model, Vtable Geometry & Dispatch Polymorphism
  • Object Anatomy: Objects with virtual methods have a hidden 8-byte pointer (__vptr) at offset 0 pointing to the class's read-only Vtable in .rodata.
  • Vtable Layout: [Offset-to-top] $\to$ [RTTI typeinfo*] $\to$ [Virtual Func Pointers vfunc1, vfunc2...].
  • Dynamic Dispatch Cost: obj->foo() $\implies$ ptr->__vptr[slot](). 2 cache misses (vptr + function code), branch target buffer stall, and inhibits compiler inlining.
  • Virtual Inheritance (Diamond): Injects vbase_offset in Vtable so subobject is shared once; adds 8-byte pointer per virtual base.

8. Smart Pointers & Control Block Architecture Ownership Models
  • std::unique_ptr<T, Deleter>: Exclusive ownership. Size = 8 bytes (with stateless deleter via empty base optimization). Move-only. Zero runtime overhead vs raw pointer.
  • std::shared_ptr<T>: Size = 16 bytes (raw pointer T* + Control Block pointer). Reference counting is thread-safe (atomic increments/decrements), but pointed-to object access is NOT thread-safe.
  • Control Block: Allocated on heap containing: Strong Ref Count (atomic), Weak Ref Count (atomic), Custom Deleter, Custom Allocator.
  • make_shared vs shared_ptr(new T): make_shared does 1 single heap allocation for both object + control block (cache friendly, no memory leak on exception). Caveat: memory for T is freed only when both strong AND weak counts reach 0.

1. Modern C++20 / C++23 Language Additions Modern Systems
  • Concepts & Requires (C++20): Replaces SFINAE. Constrains template types with boolean predicates evaluated at compile time. Clean diagnostics, allows function overloading based on concept specificity (subsumption).
  • std::span<T, Extent> (C++20): Non-owning contiguous memory view (pointer + size). Replaces raw pointer + length. Zero allocation, bounds safety in debug mode.
  • std::expected<T, E> (C++23): Value-or-error return type for functional error handling. Zero dynamic allocation, zero exception unwinding penalty. Supports .and_then(), .transform() monadic chaining.
  • std::jthread & std::stop_token (C++20): Auto-joining on destruction (prevents std::terminate), cooperative cancellation via atomic stop tokens.
  • Ranges & Views (C++20/23): Composable pipelines (vec | views::filter(...) | views::transform(...)) with lazy evaluation and zero intermediate vector copies.
  • Coroutines (C++20): Stackless, cooperatively-yielded state machines (co_await, co_yield, co_return). Allocates frame on heap (or elided via HALO).
2. C++ Memory Model & Atomic Synchronization Hardware Barriers

Hardware Reordering: CPUs use store buffers and out-of-order execution. std::memory_order dictates compiler & hardware barrier placement.

3. Lock-Free SPSC Ring Buffer (Cache-Aligned C++20) Zero Malloc Hot-Path 
template<typename T, size_t Cap>
class SPSCQueue {
  static_assert((Cap & (Cap - 1)) == 0, "Capacity must be power of 2");
  alignas(64) std::atomic<size_t> head_{0};
  alignas(64) std::atomic<size_t> tail_{0};
  alignas(64) T buffer_[Cap];
public:
  bool push(const T& item) { // Producer Core Only
    const size_t t = tail_.load(std::memory_order_relaxed);
    if (t - head_.load(std::memory_order_acquire) >= Cap) return false;
    buffer_[t & (Cap - 1)] = item;
    tail_.store(t + 1, std::memory_order_release);
    return true;
  }
  bool pop(T& item) { // Consumer Core Only
    const size_t h = head_.load(std::memory_order_relaxed);
    if (h == tail_.load(std::memory_order_acquire)) return false;
    item = buffer_[h & (Cap - 1)];
    head_.store(h + 1, std::memory_order_release);
    return true;
  }
};

5. Top 10 High-Frequency Senior Interview Traps Pitfalls
  • 1. Object Slicing: Passing derived object by value to a function taking base Base b slices off all derived state and vptr. Always pass by reference: const Base&.
  • 2. Dangling Lambda Reference: Default capture [&] capturing stack variable when lambda outlives scope (e.g. dispatched to thread pool). Use explicit move capture: [x = std::move(x)].
  • 3. Virtual Calls in Ctor/Dtor: Calling virtual methods in base constructor calls Base version, NOT Derived. Derived vtable is not initialized until Base finishes ctor.
  • 4. Modifying Container While Iterating: Calling vec.erase(it) without reassigning it = vec.erase(it) leaves dangling iterator and causes crash.
  • 5. Member Initialization Order: Class members initialize in the order they are declared in the class, NOT the order listed in the constructor initializer list.
  • 6. Throwing Destructors: A destructor throwing an exception during stack unwinding causes immediate std::terminate(). Destructors must remain noexcept.
  • 7. Static Initialization Order Fiasco: Non-local static variables in different TUs have unspecified init order. Fix: Meyers' Singleton (static local in function).
  • 8. Multi-Threaded shared_ptr Race: Control block ref-counts are atomic, but reading/writing pointed-to data across threads is NOT thread-safe. Protect with mutex or use std::atomic<shared_ptr>.
  • 9. Non-Virtual Base Destructor: Deleting a derived object through a base pointer Base* b = new Derived(); delete b; causes UB and resource leaks. Base dtor must be virtual.
  • 10. Signed Integer Overflow: Signed overflow is UB in C++ (compiler may optimize away x + 1 > x). Unsigned overflow is defined as modulo $2^N$.
6. The 12 Golden Rules of Systems Programming Commandments
  • 1. Prefer Values: Prefer stack allocations and std::vector over pointer indirection for cache locality.
  • 2. Enforce RAII: Never hold an unmanaged OS handle or raw pointer. Release in destructor deterministically.
  • 3. Zero Malloc in Hot-Paths: Pre-allocate pools, static rings, and buffers during initialization.
  • 4. Use alignas(64): Isolate atomic variables accessed by different threads onto distinct cache lines.
  • 5. Mark Moves noexcept: vector::push_back falls back to expensive deep copy if move ctor is not noexcept.
  • 6. Replace SFINAE with Concepts: Use C++20 template<typename T> requires ... for clearer compiler errors.
  • 7. Pass Sink Arguments by Value: Take by value and std::move into member to support both lvalues and rvalues.
  • 8. Const-Correct Interfaces: Mark methods const; use constinit to guarantee zero runtime init latency.
  • 9. Replace Exceptions in Hot-Path: Use std::expected<T, E> for deterministic zero-overhead error dispatch.
  • 10. Guard Against False Sharing: Verify memory layout with pahole or compiler layout dump flags.
  • 11. Never Detach Threads: Use std::jthread with cooperative cancellation via stop_token.
  • 12. Profile Before Optimizing: Measure with Linux perf stat -e cache-misses,branch-misses and Google Benchmark.
