1. Compilation Pipeline & ODR ISO/IEC 14882 §6
  • Pipeline: Preprocessing (#include, macros) → Compilation (AST, optimization, code-gen to .o) → Linking (resolves symbols across TUs & static/shared libs).
  • Translation Unit (TU): A preprocessed source file + all included headers.
  • One Definition Rule (ODR):
    • Within a single TU: An entity can have at most one definition.
    • Across multiple TUs: Non-inline functions/variables must have exactly one definition across the entire program. Inline functions, templates, and class types can be defined in multiple TUs if definitions are identical token-by-token.
  • ODR Violation: Silent Undefined Behavior (UB) — linker is not required to diagnose; often selects an arbitrary symbol, causing subtle corruption.
2. Value Categories Taxonomy Expressions

Every C++ expression has a type and a value category:

Category Identity? Movable? Definition & Examples
lvalue Yes No Named variable, function, reference to object: x, *ptr, arr[0], ++i, string literal "abc".
xvalue Yes Yes eXpiring object: std::move(x), cast to rvalue ref static_cast<T&&>(x), member of rvalue f().m.
prvalue No Yes Pure rvalue (computes value): literal 42, temporary T(), arithmetic x + y, lambda expression.
Hierarchy: glvalue = lvalue ∪ xvalue (has identity). rvalue = prvalue ∪ xvalue (can be stolen/moved).
3. std::move vs. std::forward Zero-Cost Casts
  • std::move(x): Unconditional static cast to remove_reference_t<T>&&. Does not move any bytes! Signals that resources of x may be pillaged.
  • std::forward<T>(arg): Conditional cast. Yields rvalue ref if T was deduced as non-reference; yields lvalue ref if T was deduced as lvalue ref.
  • Reference Collapsing Rules:
    & + & → & | & + && → & | && + & → & | && + && → &&
  • Universal / Forwarding Reference: T&& in a type-deducing context (template or auto&&). If initialized with lvalue, T = U&; if rvalue, T = U.
template<typename T>
void wrapper(T&& arg) {
    target(std::forward<T>(arg)); // Preserves original value category
}
4. Memory Layout & Strict Aliasing Hardware Reality
  • Virtual Segments: Text (code), Rodata (constants), Data (init globals), BSS (zero-init globals), Heap (grows up), Stack (grows down).
  • Alignment: Object of size $S$ and alignment $A$ must reside at address $Addr \equiv 0 \pmod A$. Compiler inserts padding bytes to satisfy alignment.
  • alignas(N) / alignof(T): Enforces custom alignment (e.g. alignas(64) to avoid CPU false sharing across cache lines).
  • Strict Aliasing Rule: Pointers of distinct types cannot alias the same memory address. Compiler assumes float* never points to int*, reordering instructions.
    • Exceptions: char*, unsigned char*, std::byte*.
    • Correct Type Punning: Use std::bit_cast<To>(from) (C++20) or std::memcpy. Never use *(reinterpret_cast<T*>(&u))!

6. Behavior Classification & Safety ISO Standard
  • Undefined Behavior (UB): No requirements; compiler may generate invalid code, crash, or format disk. (e.g., signed overflow, out-of-bounds, use-after-free, null dereference, uninitialized reads).
  • Implementation-Defined: Unspecified behavior where the compiler vendor must document its choice (e.g., sizeof(int), sign extension on right shift of signed int).
  • Unspecified: Valid choice from defined set; vendor does not document (e.g., order of function argument evaluation).
Crucial Rule: Signed integer overflow is UB; unsigned integer overflow is well-defined (wraps modulo $2^N$).

1. Vtable, VPTR & Dynamic Dispatch Polymorphism
  • VPTR (Virtual Table Pointer): Embedded hidden pointer added to classes with $\ge 1$ virtual function (usually at offset 0). Costs 8 bytes per object on 64-bit systems.
  • VTABLE: Per-class static array of function pointers stored in .rodata. Contains slot per virtual function + RTTI pointer.
  • Dispatch Cost: Double pointer indirection: this->vptr[slot](this, args) → prevents compiler inlining + potential branch misprediction / cache miss.
  • Multiple Inheritance: Class has multiple VPTRs (one per base with virtuals). Passing derived to secondary base requires this pointer adjustment (offset add/sub).
  • Virtual Inheritance (Diamond Problem): Base shared uniquely via virtual base table (VBTABLE) or negative vtable offsets. Prevents duplicate state.
class Base { virtual void f(); }; // sizeof = 8 (VPTR)
class Derived : public Base { int m_x; }; // sizeof = 16 (8 vptr + 4 int + 4 padding)

3. Smart Pointer Architectural Comparison <memory>
Smart Pointer Size (64-bit) Deleter Placement Thread Safety
std::unique_ptr<T, D> 8 bytes (stateless) Part of type D Not thread-safe; exclusive.
std::shared_ptr<T> 16 bytes (2 ptrs) Type-erased in Ctrl Block Ctrl block ref-counts are atomic.
std::weak_ptr<T> 16 bytes (2 ptrs) Type-erased in Ctrl Block Must call lock() to access.
  • unique_ptr: Zero overhead over raw pointer. Move-only. Default choice for ownership. std::make_unique<T>().
  • shared_ptr: Shared ownership via heap-allocated Control Block (holds use_count, weak_count, custom deleter, allocator).
  • std::make_shared<T>: Single heap allocation for both object + control block (cache-friendly). Trade-off: memory not freed until weak_count == 0.
  • weak_ptr: Non-owning observer. Breaks reference cycles (e.g. parent-child graph). Does not prevent object destruction.
4. Exception Safety Guarantees noexcept Idiom
  • Basic Guarantee: Invariants preserved; no memory or resource leaks. State may be altered but valid.
  • Strong Guarantee: Commit-or-rollback semantics. Operation succeeds, or state remains exactly as before the call.
  • Nothrow / Nofail (noexcept): Operation is mathematically guaranteed never to throw exceptions.
  • noexcept specifier: Crucial for move constructors. If a move constructor is not marked noexcept, std::vector will fall back to copying elements during reallocation to preserve strong exception guarantee.
5. RAII & Copy-and-Swap Idiom Idioms 
class Buffer {
    size_t m_size; int* m_data;
public:
    friend void swap(Buffer& a, Buffer& b) noexcept {
        using std::swap;
        swap(a.m_size, b.m_size); swap(a.m_data, b.m_data);
    }
    // Unified assignment operator (copy AND move!)
    Buffer& operator=(Buffer other) noexcept {
        swap(*this, other);
        return *this;
    }
};

    { x.size() } → std::same_as<size_t>;
    { x.data() } → std::convertible_to<const void*>;
};

// Terse syntax usage

2. C++20 & C++23 High-Yield Additions Language Evolution
  • std::span<T, Extent>: Non-owning view over contiguous memory (pointer + length). Zero overhead, bounds-safe parameter passing.
  • std::expected<T, E> (C++23): Holds value of type T or error of type E. Monadic operations: and_then(), transform(). Zero exception overhead.
  • std::jthread (C++20): Automatically joins in destructor; supports cooperative cancellation tokens (std::stop_token).
  • Ranges & Views (C++20): Composable, lazy pipeline transformations:
    auto v = arr | std::views::filter(pred) | std::views::take(5);
  • std::mdspan (C++23): Non-owning multidimensional array view with customizable layout mapping (Row-major, Column-major, Strided).
  • Coroutines (C++20): Stackless cooperative functions using co_await, co_yield, co_return. Return custom promise types.
3. C++ Memory Model & Atomic Orders std::memory_order

Controls hardware compiler instruction reordering and CPU cache coherence barriers:

Memory Order Operation Guarantee & Usage
relaxed Load / Store Atomicity only; no ordering or sync. (Counters).
acquire Load Subsequent reads/writes cannot be reordered before this load.
release Store Prior reads/writes cannot be reordered after this store.
acq_rel RMW Combines acquire + release semantics.
seq_cst All Sequential Consistency. Globally total order (Default).
Acquire-Release Pair Pattern: Store-Release on thread A synchronizes-with Load-Acquire on thread B, ensuring all data written prior to release is visible to thread B.
4. Low-Latency & Lock-Free Ring Buffer Sub-Microsecond RT
  • False Sharing: When two threads on different cores write to distinct variables on the same 64-byte CPU cache line → bus contention & cache ping-pong.
    • Remedy: alignas(std::hardware_destructive_interference_size).
  • Wait-Free Single-Producer Single-Consumer (SPSC) Queue:
    • Separate head and tail indexes into isolated 64-byte cache lines.
    • Tail updated with memory_order_release; read with memory_order_acquire.
    • Zero mutexes, zero kernel transitions, zero heap allocation.
  • Branch Prediction Hints: [[likely]], [[unlikely]].
struct alignas(64) SpscQueue {
    std::atomic<size_t> m_head{0};
    alignas(64) std::atomic<size_t> m_tail{0};
    // Pointers separated by 64 bytes prevent false sharing!
};

2. High-Frequency Interview Pitfalls Traps
  • Object Slicing: Passing derived object by value to a base class parameter → derived members stripped away; vtable sliced to base. (Pass by const Base&).
  • Dangling Lambda References: Capturing local variables by reference [&] into a lambda that outlives the caller scope (e.g. dispatched to thread pool).
  • Virtual Calls in Ctor / Dtor: Virtual mechanism is disabled during base constructor/destructor execution! The base version is statically invoked because derived subobject does not exist yet.
  • Self-Assignment: Missing if (this == &rhs) return *this; in hand-written copy assignment operator → deletes own resources before reading.
  • Mismatched New/Delete: Allocating with new[] and freeing with delete (without brackets) → Undefined Behavior (dtors not called).
  • Static Initialization Order Fiasco: Global variables in different TUs have unspecified initialization order. Fix: Construct on first use (Meyers' Singleton).
3. The 16 Golden Rules of C++ Systems Development Day 17 Synthesis
  • 01. RAII everywhere: Acquire in constructor, release in destructor.
  • 02. Prefer Rule of Zero over Rule of Five. Use modern standard library wrappers.
  • 03. std::unique_ptr is the default smart pointer. shared_ptr only for shared ownership.
  • 04. Pass by const& for non-trivial types; pass by value only for primitives or to sink via std::move.
  • 05. Mark all non-throwing move constructors and swap functions with noexcept.
  • 06. Declare all single-argument constructors explicit to forbid implicit conversions.
  • 07. Base class destructors MUST be virtual (or protected non-virtual).
  • 08. Always mark derived overriding functions with override keyword.
  • 09. Use constexpr/consteval for compile-time computations; minimize runtime cost.
  • 10. Prefer std::string_view and std::span over const std::string& / raw pointer pairs.
  • 11. Never write using namespace std; in header files. Pollutes caller namespace.
  • 12. Initialize member variables in class declaration or constructor initializer list in declaration order.
  • 13. Avoid std::bind and raw function pointers; prefer lightweight C++ lambdas.
  • 14. In multi-threaded code, synchronize via std::atomic with acquire-release semantics.
  • 15. Pad concurrent data structures to 64 bytes to eliminate cache false sharing.
  • 16. Use std::expected or error codes for recoverable failures; reserve exceptions for exceptional events.
